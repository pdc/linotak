We look for images in the pages linked to so we can make thumbnails which are
a nearly-mandatory aspect of web sites nowadays. So we need to handle badly
specified images.

## Dealing with bogus width and height

The `width` and `height` attributes are the intrinsic dimensions of the image,
not the size it should appear on the page: there is the `style` attribute (and
style sheets in general) for controlling the size it is presented at.
As such these attributes are expressed as pure numbers. The intrisic dimensions—or
and hence the aspect ratio—can sometimes be needed by the layout engine to
render the page while the image data has not been downloaded.

In practice there has always been confusion between `width` and `height` attributes
and `width` and `height` CSS properties. Some sites erronesously put CSS lengths
in these attributes. For example, Instagram uses `width="80px" height="80px"`
in some userpics (at least they did in 2025). This page on a project to create
a [Rubik’s Noordzij Cube] has `width="100%" height="auto"`. Browsers can
make sense of this but it was breaking the Linotak scanner.

The best thing to do with such attributes is to just drop them. Should Linotak
want a representation of the image it will download the image representation,
from which the true pixel dimensions will be available.


## Do we even need these attributes?

I am fairly sure these attributes are not used until we are generating representations,
but at that point the real image data should be available and hence the attributes
from the HTML are redundant. It will mostly be used when guessing which image
is the ‘hero’ image of the page before the images have been downloaded.


## Changes

Add tests (if they are missing) and code ensuring that

1. The attributes `width` and `height` are overridden with the real image dimensions
  when they become available; and
2. The attributes `width` and `height` are left undefined if the value in the HTML
  is anythiong other than a positive integer.
